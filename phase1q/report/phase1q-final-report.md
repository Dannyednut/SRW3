## 3. The count encoding and the transition rules

`PoolCount ::= zeroP | succP(PoolCount)` (free constructors), replacing the
two integer pool counters in the TDRR state; the tag stays the 1P Int tag.
The complete row-for-row translation is specified in
`spec/count-representation.md` §2 and generated by `make_abs_q.py`
(roundtrip-verified, source-verified, fail-closed — audit §4). Key shapes:

* **commit-accept (row B-SS):** `absStQ(1,true,true,succP(G0),succP(E0),…),
  aCommitJ(aOkT,aOkT) → absStQ(1,true,true,G0,E0,N+Int 1,true,…)` — the
  structural double decrement; NO `requires`.
* **commit rejection:** rows A-Z* (`zeroP, E`), A-SZ (`succP(G0), zeroP`)
  — the empty-pool complements — and C-SS/D-SS (the bits-failed rows over
  successor-headed pools); all identity; NO `requires`.
* **gate:** row A-Z (`zeroP` refusal), row B-S (`succP(E0)` mint:
  `G ↦ succP(G)`, **E kept** — the 1P row B's exact semantics), row C-S
  (`succP(E0)` refusal); NO `requires`.
* exec-mint is the structural increment `E ↦ succP(E)`; init-accept is the
  only legal re-tag and resets both pools to `zeroP`; the incoherent-tag
  `[owise]` complement is the machine's ONLY `requires` (C3 generator
  check).
* The runner keeps the 1P branch discrimination and REPLACES the TDRR Int
  fork with the **constructor fork**: every tag-1 gate/commit ground shape
  is forked on the pool-head constructors at the `<absjshadow>` cell (a
  REWRITE position — the position 1O/1P proved the checker discriminates);
  exhaustive by free-constructor totality, carries no `requires`.

**Critical requirement, discharged:** no compound (or single) numeric pool
guard exists anywhere in the dispatch path; the pool distinctions are
constructor patterns at rewrite positions, and the machine still represents
arbitrary finite pool sizes (`succP^n(zeroP)` for every n; the exact count
is recoverable through `countToInt`).
