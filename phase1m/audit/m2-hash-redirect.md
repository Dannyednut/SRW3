# M2 hash-redirect machine (the B1 removal, measured)

**Disposition:** the hash-definedness blocker (phase1l/audit/induction-diagnosis.md

MEASURED at the claim level**: the machine's hash primitive is redirected to

## 1. The evaluator (Route 1 — the real, deterministic evaluator)

`phase1m/semantics/keccak256_total.k` (module `KECCAK256-TOTAL`; generated by
`scripts/gen_keccak_total_packed.py` — do not hand-edit): Keccak-256
(Keccak-f[1600], 24 rounds, rate 136 bytes, ORIGINAL Keccak padding 0x01..0x80
— the KRYPTO.keccak256raw convention, little-endian lanes) written in plain K
rules with **NO hooks**: the state is ONE 1600-bit Int (lane i = x+5y at bits
64i..64i+63); every stage is a fully-literal-indexed pure-Int reduction.

* **TOTAL** by the `[function,total]` annotation AND by construction: the
  padding rules partition `lengthBytes(M) modInt 136` exactly (0 / 135 /
  interior), the absorb rules partition the padded stream (`== 0` / `== 136`
  / `> 136` — the padded stream is always a positive multiple of 136), and
  every stage is a literal-indexed reduction.  `#Ceil(Keccak256T(x))`
  discharges for EVERY argument — literal, symbolic, or nested-hash.
* **DETERMINISTIC and EXACT**: pinned to 7 vectors on BOTH backends
  (`transcripts/k/kek-vectors-llvm.txt`, `kek-vectors-hs.txt` — 7/7 + 7/7;
  the references cross-checked between an independent Python implementation
  `scripts/kek_ref.py` and pycryptodome).  A full hash evaluates in ~7.6 s on
  the hs backend, ~1 s on LLVM.
* **NO hash property is assumed**: the evaluator COMPUTES; equalities remain
  claim hypotheses where they are hypotheses (the KB negative controls,
  §4).

### 1.1 The failed first attempt (of record)

The FIRST evaluator (pre-reset; a Map-keyed state with per-stage Map-update
recursions) was never vector-validated and OOM-killed the hs `krun` of the
full hash (exit 137, 4 GB host; the witness log was lost with sandbox reset
#7 — the crash is recorded verbatim in the session log).  It is preserved as
the failed attempt of record at `audit/failed-attempts/` (reconstructed from
the session record post-reset, marked as such; NOT part of the deliverable
semantics).  Three latent defects were exposed and fixed during the packed
version's vector validation (the first two inherited from that attempt):
(1) the padding zero count (`KZeros(Q -Int 2)` instead of `KZeros(134 -Int
Q)`); (2) the XOR convention — **in K, `^Int` is EXPONENTIATION (INT.pow);
bitwise XOR is `xorInt`** (the first build died computing `x**(2**64-1)`
inside `KNot64T` — SIGFPE); (3) the absorb remainder slice
(`lengthBytes(B) -Int 136` silently dropped every second block, and
`substrBytes` RAISES on start > end, so the `== 136` base rule exists).

## 2. The M2 machine (the redirect)

`phase1m/semantics/srw3closure-j-m2.k` = M1 (the L-FINDING-1-repaired
machine) with EXACTLY FIVE disclosed edits (verified by roundtrip in
`scripts/make_m2.py`): the header; `requires "keccak256_total.k"`; the module
rename; `imports KECCAK256-TOTAL`; and ONE redirect equation on the hash
PRIMITIVE:

```k
rule Keccak256raw(B:Bytes) => Keccak256T(B)
```

User equations on a hooked symbol are tried before the native
implementation, and this equation always matches — so EVERY hash caller in
the closure flows through the evaluator.  This includes `LinH`
(k/phase1d/srw3lin.k — StateRootJ / ProtoRootR3 / JCatalogRootJ /
EvidenceIDJ / the anchors) AND the frozen 1E authority path
(phase1e/semantics/srw3auth.k: `AuthLeafList` / `AuthWalkAux` /
`AuthWalkAuxList` call `Keccak256raw` DIRECTLY — discovered by the first
build's stuck-term discriminator, which had redirected only `LinH` and died
on the catalog canonicalization).  The frozen hook stays declared and linked
but is unreachable.  The redirect is a function EQUATION — no transition
rule is added; the M2 reachable rule set is the frozen 1J rule set + the ONE
L-FINDING-1 repair + this equation.
