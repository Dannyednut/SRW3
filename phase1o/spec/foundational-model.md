# SRW3 Phase 1O — the foundational model (mandate §4)

**Status:** the model of record for the Source-Preserved Transitions (SPT)
investigation. Level III only; no consensus-integration claim anywhere.

## 0. Reading guide

This document defines the mathematical objects the phase reasons about,
separates the six classes of predicates the mandate requires, states the
proof obligations P1–P6, and declares — for each object — WHERE it lives
mechanically (which K definition, which claim). Nothing here is claimed
proved unless a retained, classified artifact establishes it; §7 maps
every obligation to its current status.

## 1. The state space and the machines

### 1.1 The concrete machine (M3, frozen)

The M3 machine (`phase1m/semantics/srw3closure-j-m3.k`, byte-identical in
this tree) is the concrete state space:

* \(S_{M3}\): configurations of the `<srw3closureJ>` machine — nine cells
  (`<k>`, `<jlineage>`, `<jnext>`, `<jhead>`, `<jlinhead>`, `<janchor>`,
  `<jstate>`, `<jrefuse>`, `<jvalid>`), with hash-class values,
  catalog/block/receipt structures, and the R3 protocol-configuration
  binding.
* The M3 transition relation is the K rewrite relation generated by the
  frozen rules; its well-formed command partition has ten transition
  classes (init accept/[owise], exec dispatch → mint ×2 / refuse ×3,
  gate mint ×2 / [owise], commit accept/[owise], the program runner) plus
  the ONE declared stall class (exec on an unpinned configuration — the
  `pExecJ` dispatch requires the pins; NO rule exists there: a stuck
  configuration).

### 1.2 The abstract machine (AM3, frozen at 1N; the R variant is 1O-only)

AM3 (`phase1n/semantics/abs-machine.k`, unchanged in 1O) is the decidable
skeleton:

* \(S = \{\,\text{absSt}(c, t, g, e, n, sf, d) \mid c,t,sf \in \mathbb{B},\;
  g,e,n \in \mathbb{Z},\; d \in \{\text{adNone},\text{adSource},
  \text{adExecRefuse},\text{adGate}\}\,\}\).
* The abstract commands \(ACmd\) carry every input-dependent guard outcome
  as an EXPLICIT constructor bit: \(aInitJ(b)\), \(aExecJ(b, s)\),
  \(aGateJ(b)\), \(aCommitJ(b_1, b_2)\) with \(b,b_1,b_2 \in
  \{\text{aOkT},\text{aOkF}\}\), \(s \in \{\text{aSrcAuth},\text{aSrcOther}\}\)
  — twelve ground command shapes.
* The abstract step \(absStepJ: S \times ACmd \to S\) is total and
  `[owise]`-partitioned — the exact class-mirror of M3's ten classes plus
  the honest stall (the function-level identity on exec-on-unpinned).
* The abstract run fold \(absRunF: PProg \times S \to S\) composes steps.
* The R variant (`phase1o/semantics/abs-machine-r.k`, GENERATED — one
  disclosed edit) lifts the runner's command dispatch to the rewrite level
  (twelve ground-command rules + an `[owise]` complement that cannot fire
  on a ground command). `absStepJ`, `ABSInv`, `simJ`, `absExecutable`,
  `absRunF` are byte-identical. Its role: the §6 reproduction showed the
  1N runner shape cannot dispatch symbolic commands in proof; the R shape
  is the strongest formulation the toolchain can explore.

## 2. The predicates, separated (mandate §4's six distinctions)

1. **State validity.** \(Valid(s)\): the configuration is well-formed —
   on the abstract side, membership in \(S\) (total; every `absSt` term is
   a state); on the concrete side the M3 configuration discipline
   (the `<jvalid>` cell, the key-reservation discipline of the lineage
   map). Validity is PRECONDITION machinery, never a conclusion carrier.
2. **Transition validity.** \(T_F(s,s')\): the permitted-transition
   relation (§3 below). A transition is valid when a well-formed command
   of the responded class fires from \(s\) to \(s'\); refusals and the
   stall are explicit non-committing classes.
3. **Foundational specification identity.** The foundational
   specification \(F\) is FIXED by the frozen artifacts: the invariant
   \(Safe_F\) is `ABSInv` (abstract) with its concrete counterpart
   \(JInvPlusJ\) (1L, frozen); the transition contract is the frozen M3
   rule partition; the authority model is the R3 configuration commitment.
   \(F\) is a GIVEN of the model — it is not a state-dependent datum, and
   no rule of any machine writes it.
4. **Authorization to change the specification.** \(Auth_F\): there is NO
   modeled rule by which an application changes \(F\), \(Safe_F\), or its
   own authority. The only authorization channel is the protocol-level
   configuration commitment (R3: the anchor cell `<janchor>` is
   protocol-authored input; NO rule writes it) and the init guard's
   catalog/root checks. In the SPT framing this is the P4 obligation: the
   model makes unauthorized change UNEXPRESSIBLE rather than forbidden —
   the strongest available form (see §6).
5. **Execution-evidence authenticity and completeness.** The hash-class
   bindings (the R3 root match, the anchor, the receipt digests, the block
   commitments) are the evidence layer. Inherited assumption A-EV (from
   1E–1M, unchanged): hash authenticity and collision-freedom are
   ASSUMED, never derived; the simulation claims carry every hash-class
   equality as the concrete machine's OWN guard hypothesis (discharged
   per-execution by the concrete guards), and the abstract side never
   evaluates a hash equality. Evidence completeness (no omitted write) is
   covered only for the modeled fragment (A-FRAG, below).
6. **Protocol acceptance and commitment.** \(Commit_F(s, e)\): the
   accept-commit class — the concrete rule's own 24-conjunct guard (both
   pools nonempty with the matching gate receipt, the accept guard, the
   COMPUTED `SafeJ` on the derived post-state, the slot/lineage
   bookkeeping); on the abstract side, `absStepJ`'s commit-accept rule
   with the `(aOkT, aOkT)` bits and `g >= 1 ∧ e >= 1`. Only this class
   advances the slot.

## 3. The permitted-transition relation \(T_F\)

\[
T_F(s, s') \;\equiv\; \exists c \in ACmd.\;
  absExecutable(c::RUN, s) \;\land\; absStepJ(s, c) = s' \;\land\;
  \text{the class of } (s,c) \text{ is responded.}
\]

The responded-command domain is `absExecutable` (frozen 1N): the ONE
non-responded class is exec-on-unpinned (the honest stall). Refusals
(source/exec-refuse/gate/refuse-classes and the commit reject) ARE
transitions — non-committing ones: they write at most the diagnostic
class and preserve every invariant cell.

**Permitted variation vs forbidden mutation (mandate §5).** The
specialization relation a source-application may exercise, without
changing \(F\):

* MAY vary: the application's command stream (any finite \(PProg\)), the
  pool contents up to the class guards, the diagnostic history, all
  state fields the classes leave framed.
* MUST preserve: every conjunct of \(Safe_F\) (§4) after every accepted
  transition; the diagnostic write-discipline (refusals write nothing
  else); the non-commitment of refusal/stall/reject classes.
* REQUIRES authorization (and in this model has no rule): changing
  \(Safe_F\), the class partition, the commitment predicate, or the
  anchor.
* MUST be refused: commits without both receipts on matching slots
  (the guard's own conjuncts), commits whose derived post-state fails
  the computed `SafeJ`, exec/gate/commit from invalid states, sources
  other than the authorized executor.
* INVALID states: mixed-pin valuations (exactly one pin set) — excluded
  from the invariant by definition (`ABS-INV-EXCL-I/II`).
* MISSING evidence: any hash-class binding mismatch makes the concrete
  guard fail (the refusal classes) — under assumption A-EV.

## 4. The foundational safety predicate

\[
Safe_F(\text{absSt}(c,t,g,e,n,sf,d)) \;\equiv\;
(\neg c \land \neg t \land g = 0 \land e = 0 \land n = 0)
\;\lor\;
(c \land t \land g \ge 0 \land e \ge 0 \land sf).
\]

This is `ABSInv` (frozen 1N, byte-identical in 1O) — the decidable
counterpart of the two branches of the frozen \(JInvPlusJ\): the pre-init
branch and the initialized branch. The `sf` bookkeeping bit is SET only by
the abstract init (whose concrete counterpart's guard COMPUTED
`SafeJ(P, .Map)`) and CARRIED only by the accept-commit (whose concrete
guard COMPUTED `SafeJ` on the derived post-state, presented as the second
bit). **The declared boundary (1N abstraction register, unchanged):** the
transfer \(sf = \text{true} \Rightarrow SafeJ(P, \text{concrete state})\)
is NOT a mechanized theorem; it is the conformance obligation discharged
per-execution by the concrete guards (the 1L stuck-symbolic class).
\(Safe_F\) does NOT contain its own persistence as an assumption — the
step must re-derive it (the negative controls enforce this).

## 5. Initial states

\(S_0 = \{\,\text{absGenesis}\,\} = \{\text{absSt}(\bot,\bot,0,0,0,\bot,
\text{adNone})\}\) on the abstract side, modulo the unconstrained
diagnostic class (the M3 pre-init refusals write diagnostics while every
invariant cell stays at the genesis values). On the concrete side the
genesis configuration of the M4 machine.

## 6. The commitment boundary and the authority model

\(Commit_F\) fires exactly on the accept-commit class; its guard is the
machine's own rule (not a derived property). The authority model:
the anchor is protocol-authored and rule-immutable; the catalog is pinned
once by the init guard against the R3-rooted configuration; NO rule
rewrites \(F\), \(Safe_F\), or the guard definitions. Consequently the
P4 property holds in the model by CONSTRUCTION (unauthorized change is
unexpressible), which is the honest strength limit: the model cannot
represent an application that redefines validity, only one that presents
states/commands/evidence — and those are exactly what the guards
constrain. What the model does NOT establish: that the concrete
implementation (LLVM/Python layers, or any real protocol code) preserves
the construction (assumption A-IMPL), nor that the cryptographic
bindings hold (A-EV), nor consensus integration (Level III).

## 7. The proof obligations and their standing (see the final report §7 for the full ledger)

| Obligation | Statement | Standing after 1O |
|---|---|---|
| P1 Initial safety | \(\forall s_0 \in S_0.\; Safe_F(s_0)\) | MECHANIZED (evaluation: `ABS-INIT-BASE-INV`; the genesis satisfies the preinit branch) |
| P2 Universal transition preservation | \(Safe_F(s) \land T_F(s,s') \Rightarrow Safe_F(s')\) | PER-CLASS MECHANIZED (the 21-claim branch-complete `ABS-PRESV` family, re-proven in 1O); the UNIFORM statement is the blocked one (§6 obstacle) |
| P3 Finite-reachability safety | every finite execution from \(S_0\) stays in \(Safe_F\) | NOT MECHANIZED for symbolic programs (the composition boundary — the §6 investigation, retained residuals); mechanized for concrete pipelines (`ABS-RUN-*`, `1O-RUN-*`) |
| P4 Specification authority | an application cannot alter \(F\) | HOLDS BY CONSTRUCTION in the model (no rule can express the change); NOT a theorem about any implementation |
| P5 Concrete-to-abstract correspondence | concrete steps covered by the abstract model | CLASS-WISE MECHANIZED (the SIM shape claims — hash equalities as hypotheses) + the counting algebra (9 claims); the mint-class shape claims retain the B5' timeout |
| P6 Commitment soundness | acceptance at the boundary carries the stated conclusion | CLASS-WISE (SIM-COMMIT-ACCEPT, the machine's own map-update destination form); the universal commit-safety statement inherits the P3 boundary |

**The standing assumptions of record (inherited, unchanged):** A-EV
(cryptography/hashes), A-FRAG (the bounded execution fragment of 1J),
A-R3 (the R3 configuration commitment), A-IMPL (the correspondence of the
implementation layers), and the SafeJ-conformance obligation (per-
execution, not mechanized). No new assumption is introduced by 1O.
